# Counterpart Map

Two modes. Figure out which one from the request.

**Prep** — "I need to talk to X about Y", "how do I raise this with X", "meeting with X in an hour", "where should I bring this up".

**Debrief** — a pasted transcript or Slack thread, "here's how it went", "review this exchange", "did that land".

If the request is specifically *giving someone critical feedback*, hand off to the `constructive-feedback` skill instead. This skill is for everyday interaction and for learning from it.

## Read the source first — always

The profiles are **not** in this skill. They live where they can be kept current:

- Project **Klever tech Scrum**: `gab-delivery-and-interaction-map.md` (per-person map, Gab's own habits), `where-to-raise-what.md` (which venue for which topic), `agreements-ledger.md` (what's already settled — check before treating a frustration as new)
- Memory: `/people/*.md` for each colleague, `/topics/communication.md` for Gab's own patterns

Read the relevant ones before answering. Never work from what's written below alone — treat it as a fallback that may be out of date, and say so if the sources aren't reachable.

## Prep mode

Produce four things, short:

1. **Style brief** — how this person receives information, from their profile. What lands, what gets absorbed with no effect.
2. **Venue** — where this topic belongs, per `where-to-raise-what.md`. If the venue is wrong, say so before anything else; the right message in the wrong room still fails.
3. **The ask, in one sentence** — request first, context only if they ask. If the draft explains before asking, rewrite it.
4. **Traps to watch** — pull from Gab's habit list and name the one or two most likely to fire with this person.

Don't write a script unless asked. A one-sentence ask plus a named trap beats a rehearsed paragraph.

## Debrief mode

When given a transcript or thread:

**Attribution first, and never guess.** Ask who was in the conversation if it isn't stated. Do not infer a name from content, and never take a name from transcript tooling metadata or a suggested rename command — that has produced a wrong attribution before. If speakers are unlabeled, ask.

Then:

1. **The three counts** — how many times did Gab say "make sense?" / "you understand?"; how many asks led with the request rather than the context; how many points were made once and dropped rather than returned to.
2. **What worked** — quote it. Especially rephrasing-back, fast concession on a side point, and any mechanical ask that got a commitment.
3. **What cost him** — quote it. Trait apologies, self-undercutting mid-sentence, long preamble, validation-seeking.
4. **New evidence about the counterpart** — anything they revealed about how they work, in their own words.
5. **Proposed updates** — concrete lines to add to the relevant `/people/` memory file or project doc. Offer them; write them when Gab says yes.

Quote actual words rather than characterizing. Gab has said repeatedly that seeing the pattern written is what makes it usable.

## Gab's delivery — the standing watchlist

**Traps**
- "Make sense?" / "you understand?" — closes a point then reopens it. Replace with silence. Highest leverage, and countable.
- Explanation before ask — long context, then the request. Invert it.
- Reflexive apology — one apology for a named act is repair and is fine. Apologizing for a trait, or twice, or for the conversation itself, is not.
- Negotiating against himself mid-sentence — states a position, retracts, restates, hedges. Same shape he finds frustrating in others.

All four are one habit: wanting confirmation. One practice, not four.

**Strengths — protect these**
- Rephrasing back: "So what I'm hearing is X. Is that right?" Forces vague input into something checkable, and doubles as his memory check.
- Asking for feedback without defending.
- Conceding fast on whatever isn't the point.

**On humility.** It attaches to *authority*, not to *certainty*. Be certain about the observation, deferential about the decision. "The sprint has 61 items, we close 30, your call what comes out" is more humble than a hedged version, not less — it claims no authority and imposes no decoding work. Clarity is the humble move; hedging makes the other person carry the load.

## Two axes that matter for routing

**Nerd-out vs brainstorm.** Nerd-out is depth on a known thing, converging. Brainstorm is breadth on an unknown, diverging. Some people want the first and refuse the second. Exploratory thinking is a real need of Gab's — route it to people who want it, deliver conclusions to people who don't.

**Internal state vs named behaviour.** With some counterparts, explaining how something feels gets absorbed with no effect, while naming a concrete behaviour gets an immediate commitment. When a profile says this, never lead with feelings — lead with the mechanism.

## Measurement

When asked how it's going, report only the three counts over the period, with quotes. Movement in those three is the whole signal.
