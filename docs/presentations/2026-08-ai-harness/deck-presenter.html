No database. No index server. No special format. Plain folders and text files that point at each other. Every piece can be read by a human, edited by hand, diffed and tracked in git. That is why it survives when the tools change.

Index, then metadata, then the one page. Never bulk load. I can add another 600 pages tomorrow and the cost of starting a session does not move.
The library

A library, not a chat history

Give it less, not more

Klever has far more detail than fits in one context. Dumping it all in makes the answer worse. Indexed, it finds the one page it needs.

It's just files

A constellation of plain files that point at each other, and an agent that reads them. No database required.

It compounds

A session on Monday knows what I learned in April. Chat history evaporates.

The floor

Built upside down, on purpose

Tests before code

We write the proof of "done" first. The agent then has to satisfy it. It never declares victory on its own terms.

Orange boxes block

It can argue with me. It cannot argue with a script that returns exit code 1.

Yellow boxes are me

One decision at the front, one approval at the end. Not every step in between.

Second habit

Make it prove, and it lies less

My standing rule for any bug
give me the line. who wrote it. when. and why you think it was written.

It cannot invent a line number it has to cite.

Example — hunting a bug

this line is 2 months old
→ the bug is new. probably not it.

this line changed yesterday
→ that's my suspect.

Asking for proof doesn't only verify the answer.
It changes how it thinks.

Two things, neither needs code

1
Keep a library, not a chat history
  • Every session that teaches you something leaves something behind
  • A file, a folder, a set of files that point at each other
  • Your rules live in there too, and it reads them every time
  • Index it, so it loads the one page it needs
2
Make it prove, not tell
  • Ask for the source, the screenshot, the line, the link
  • When it apologises for skipping a step, that apology is the rule
  • Write it down and it can't happen twice

You don't need 118 skills to start. You need one file and the habit of adding to it.
