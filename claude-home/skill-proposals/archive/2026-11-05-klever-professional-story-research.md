## Trigger

Research professional case studies, presentations or feature demos across Klever local repositories and project-management records, using actual implementation history and accurate shared attribution.

## Scope

Klever organization. Reuse existing repository discovery, source tools and bibliography procedures; avoid creating another domain knowledge store. User-specified read-only, no-fetch and publication boundaries govern the workflow.

## Draft Steps

1. Discover actual git clones, applicable instructions and available refs. Record source freshness and output-only write authorization. Group leads into connected stories; keep unpublished threads separate.
2. Follow diffs, resulting trees, renames, branch disposition and later corrections. Capture full SHA, author/committer dates, file paths and immutable credential-free URLs; verify claimed removals through callers/background/fallback paths.
3. Build an evidence ledger separating implementation, integration, deployment, historical validation, current behavior, measured outcomes and predictions. Attribute requirements, decisions, implementation, review and recovery separately from AI/commit identity.
4. Write business-readable narratives with optional technical depth and synthetic demo suggestions. Put research/access caveats and exact evidence in separate appendices; retain explicit holds instead of inventing missing original material. Exclude private conversations, credentials, client-sensitive details and local configuration.
5. Check each narrative claim against its evidence and later corrections. Deliver separate files using absolute clickable local paths, web source citations, an index and no more than three consequential questions. Do not fetch, commit, push, publish or contact anyone without applicable authorization.
